# ゲーム理論の基本用語

この文書は、各Studyで使うゲーム理論とsolverの用語を、toy pokerを読むために必要な範囲へ絞って説明します。

## ゲームの構成要素

| 用語 | 意味 | このプロジェクトでの例 |
|---|---|---|
| プレイヤー | 意思決定を行う主体 | OOPとIP |
| アクション | ある局面で選べる行動 | Check、Bet、Call、Raise、Fold |
| 履歴 | rootから現在までに行われたアクション列 | `OOP Check → IP Bet 50%` |
| ノード | ある履歴に対応するゲーム木上の局面 | root、betに直面した局面など |
| 終端ノード | 勝敗と利得が確定し、それ以上アクションがない局面 | Fold後、Showdown後 |
| 利得 | そのプレイヤーがゲームから受け取る数値 | 初期potを含む最終チップ増減 |
| 情報集合 | プレイヤーから区別できないノードの集合 | 自分のrankと履歴は同じだが、相手rankが異なる局面 |
| 到達確率 | 方策とカード分布に従って、その局面へ到達する確率 | Viewerのreach確率 |

このプロジェクトでは初期pot 1を誰の拠出ともみなさないデッドマネーとして扱います。そのため、全ての
終端ノードでOOPとIPの利得合計は1です。これはzero-sumではなくconstant-sumですが、一方の利得から
定数0.5を引けば通常のzero-sum表現と同じ戦略問題になります。

## 戦略と方策

### 純粋戦略

ある情報集合で常に同じアクションを選ぶ戦略です。`Aで100% All-in`や`Kで100% Check`が該当します。
純粋戦略になる理由は、通常、そのアクションの期待利得が他の全アクションより高いからです。

### 混合戦略

複数のアクションを確率的に選ぶ戦略です。例えば`QでAll-in 50% / Check 50%`です。均衡で内部混合
（各頻度が0%でも100%でもない）が現れるとき、そのプレイヤー自身の各アクションの期待利得は等しくなります。

重要なのは、混合頻度を決める式が、多くの場合「混合する本人」ではなく「相手を無差別にする条件」から
得られることです。K vs AQでは、Qのbluff頻度はOOPのKをCall/Foldで無差別にするように決まり、OOPの
Call頻度はIPのQをBet/Checkで無差別にするように決まります。

### 行動方策

各情報集合で各アクションを選ぶ確率の表です。CFR系solverとStrategy Viewerが表示するのは、この
行動方策です。本Studyでは文脈上明らかな場合、行動方策も単に「戦略」と呼びます。

## 期待利得と最適反応

ある戦略組に対する期待利得（EV）は、カード配布と全アクションの確率で終端利得を重み付けした平均です。

最適反応（best response）は、相手の戦略を固定したとき、自分の期待利得を最大にする戦略です。
相手が特定のrankでbluffしすぎるならCallを増やし、bluffが少なすぎるならFoldを増やす、といった
最大限の攻略を行います。

## Nash均衡

互いの戦略が相手に対する最適反応になっており、どちらか一方だけが戦略を変えても期待利得を増やせない
状態です。Nash均衡は「全アクションの頻度が唯一」という意味ではありません。期待利得が同じアクションや、
到達しない枝では、異なる混合が同じ均衡価値を持つことがあります。

## 無差別条件

混合戦略を正確に導く中心的な道具です。アクション $a_1,a_2$ を正の頻度で混ぜるなら、

$$
EV(a_1)=EV(a_2)
$$

でなければなりません。もし $EV(a_1)>EV(a_2)$ なら、$a_2$を選ぶ頻度を0にして$a_1$だけを選ぶ方が
有利だからです。各Studyでは次の順序で混合を導きます。

1. 相手のprivate handごとに、各アクションの利得を書く。
2. カード確率と相手の混合頻度で期待利得を作る。
3. 混合させたい2アクションの期待利得を等置する。
4. 得られた頻度が0〜1に入り、未使用アクションの利得がそれ以下であることを確認する。

## Exploitability

Exploitabilityは、現在の戦略が完全な最適反応からどれだけ攻略され得るかを表す収束指標です。本プロジェクトの
2人constant-sumゲームでは、両プレイヤーのbest-response improvementの平均として表示します。0ならNash均衡、
小さいほど均衡に近いことを意味します。

ただし、全体のExploitabilityが小さくても、到達確率が極端に低い情報集合の方策は不安定な場合があります。
個別頻度を読むときはreach確率とAction EVも確認します。

## Counterfactual regretとCFR

Counterfactual regretは、「その情報集合へ自分以外の要因で到達したと仮定したとき、別アクションを選んでいれば
どれだけ得だったか」を累積した値です。CFRは各情報集合でこの後悔を小さくし、平均方策をNash均衡へ近づけます。
CFR+は負の累積後悔を0へ切り上げ、DCFRは古い後悔を割り引くことで収束を速める派生手法です。

## Node lock

特定の情報集合・rankの戦略を外部から固定し、残りだけを最適化する機能です。lock付き結果は元ゲーム全体の
Nash均衡ではなく、固定条件下の均衡です。そのため収束判定には、lockを守る戦略集合内の
constrained Nash gapを使います。
