# 基礎 ① ゲーム理論の基本用語

この文書は、各 Study で使うゲーム理論と solver の用語を、toy poker を読むために必要な範囲へ絞って説明します。

---

## ゲームの構成要素

| 用語 | 意味 | このプロジェクトでの例 |
| --- | --- | --- |
| プレイヤー | 意思決定を行う主体 | OOP と IP |
| アクション | ある局面で選べる行動 | Check、Bet、Call、Raise、Fold |
| 履歴 | root から現在までに行われたアクション列 | `OOP Check → IP Bet 50%` |
| ノード | ある履歴に対応するゲーム木上の局面 | root、bet に直面した局面など |
| 終端ノード | 勝敗と利得が確定し、それ以上アクションがない局面 | Fold 後、Showdown 後 |
| 利得 | そのプレイヤーがゲームから受け取る数値 | 初期 pot を含む最終チップ増減 |
| 情報集合 | プレイヤーから区別できないノードの集合 | 自分の rank と履歴は同じだが、相手 rank が異なる局面 |
| 到達確率 | 方策とカード分布に従って、その局面へ到達する確率 | Viewer の reach 確率 |

このプロジェクトでは初期 pot 1 を誰の拠出ともみなさないデッドマネーとして扱います。そのため、全ての終端ノードで OOP と IP の利得合計は 1 です。これは zero-sum ではなく constant-sum ですが、一方の利得から定数 0.5 を引けば通常の zero-sum 表現と同じ戦略問題になります。

---

## 戦略と方策

### ・戦略

各情報集合で各アクションを選ぶ確率を定義した、行動計画です。

### ・純粋戦略

ある情報集合で常に同じアクションを選ぶ戦略です。`Aで100% All-in`や`Kで100% Check`が該当します。純粋戦略になる理由は、通常、そのアクションの期待利得が他の全アクションより高いからです。

### ・混合戦略

複数のアクションを確率的に選ぶ戦略です。例えば`QでAll-in 50% / Check 50%`です。ナッシュ均衡で混合戦略が現れるとき、各アクションの期待利得は等しくなります。

---

## ナッシュ均衡と最適反応

### ・最適反応

最適反応（best response）は、相手の戦略を固定したとき、自分の期待利得を最大にする戦略です。

### ・Nash 均衡

互いの戦略が相手に対する最適反応になっており、どちらか一方だけが戦略を変えても期待利得を増やせない状態です。

### ・無差別条件

混合戦略を正確に導く中心的な道具です。アクション $a_1,a_2$ を正の頻度で混ぜるなら、

$$
EV(a_1)=EV(a_2)
$$

でなければなりません。もし $EV(a_1)>EV(a_2)$ なら、$a_2$を選ぶ頻度を 0 にして$a_1$だけを選ぶ方が有利だからです。各 Study では次の順序で混合を導きます。

1. 相手の private hand ごとに、各アクションの利得を書く。
2. カード確率と相手の混合頻度で期待利得を作る。
3. 混合させたい 2 アクションの期待利得を等置する。
4. 得られた頻度が 0〜1 に入り、未使用アクションの利得がそれ以下であることを確認する。

### ・Exploitability

Exploitability は、現在の戦略が完全な最適反応からどれだけ攻略され得るかを表す収束指標です。本プロジェクトの 2 人 constant-sum ゲームでは、両プレイヤーの best-response improvement の平均として表示します。0 なら Nash 均衡、小さいほど均衡に近いことを意味します。

ただし、全体の Exploitability が小さくても、到達確率が極端に低い情報集合の方策は不安定な場合があります。個別頻度を読むときは reach 確率と Action EV も確認します。

## Counterfactual regret と CFR

Counterfactual regret は、「その情報集合へ自分以外の要因で到達したと仮定したとき、別アクションを選んでいればどれだけ得だったか」を累積した値です。CFR は各情報集合でこの後悔を小さくし、平均方策を Nash 均衡へ近づけます。 CFR+は負の累積後悔を 0 へ切り上げ、DCFR は古い後悔を割り引くことで収束を速める派生手法です。

## Node lock

特定の情報集合・rank の戦略を外部から固定し、残りだけを最適化する機能です。lock 付き結果は元ゲーム全体の Nash 均衡ではなく、固定条件下の均衡です。そのため収束判定には、lock を守る戦略集合内の constrained Nash gap を使います。
